# SVNWorkBench

Tkinter 图形界面的 SVN 工作台（检出 / 更新 / 提交 / 双击对比 / 仓库浏览 /
提交历史）。

**零第三方依赖**：只需要 Python 3.5.2+ 标准库和 svn 命令行客户端，
不需要 pip 安装任何包。tkinter 随 Python 附带，Debian/Ubuntu 缺失时
执行 `sudo apt install python3-tk` 即可。可选：装了 `meld`
（`sudo apt install meld`）时双击差异会询问用 meld 还是内置窗口
（可记住选择，之后在顶栏"对比方式"或改动列表右键菜单里改回来），
没装 meld 则直接用内置窗口。

**最小部署**：程序目录只需保持入口 `SVNWorkBench.py` 与 `svnwb/` 包
（`tests/` 是随仓库的回归测试脚本，部署时不必拷贝）。配置与日志都不在
程序目录，见下文「配置与日志」。

## 运行

```bash
python3 SVNWorkBench.py                    # 正常启动
python3 SVNWorkBench.py /path/to/wc        # 带启动参数：直接打开该工作副本
```

启动即打开主窗口，关窗退出。**启动参数是工作副本目录**：启动后自动把它
填进工作副本框、**先清空地址框**再用 `svn info` 反查地址；**反查成功才
写入配置并刷新改动列表**——路径不是 SVN 工作副本时地址保持留空，也不
记录到配置（下次启动不会带出无效路径；详见下节「文件管理器右键集成」）。
目录"浏览"按钮优先调用系统 `zenity`
目录选择框（跟随系统语言），缺失时自动回退 Tk 自带选择框。

## 配置与日志（都不在程序目录）

- **配置**：`~/.config/SVNWorkBench/_settings.json`（尊重 `XDG_CONFIG_HOME`），
  只有一个文件——工作副本、SVN 地址、排除清单、证书选项、对比方式、皮肤
  （`theme`）、仓库浏览器的最近地址（`recent_repo_urls`，最多 10 条）。
  可用环境变量
  `SVNWB_CONFIG_DIR` 覆盖目录。旧版（v4 及以前）配置在程序同级
  `configs/_settings.json`，首次启动自动**一次性迁移**到新位置，
  字段只搬还没填过的，旧文件原样保留不删除（工程已不再附带 `configs/`
  目录，但迁移逻辑保留：旧版本用户把新程序放进旧目录仍会自动迁移）
- **运行日志**：`/tmp/SVNWorkBench-<用户名>/logs/`（每个任务一个 `.log`，
  重启即清），可用环境变量 `SVNWB_LOG_DIR` 覆盖。按用户名分子目录，
  多用户共用一台机器也不会互相踩权限
- 两者分开存放，写入都是原子的（`.tmp` + `os.replace`）

## 文件管理器右键集成（可选）

程序接受"工作副本目录"启动参数，因此可以挂进文件管理器的右键菜单。

**方式一：脚本安装（UOS/deepin、Kylin V10、Kylin V10 SP1）**

交付包里的脚本按系统放在 `dist/right-menu/<系统>/`，进入 `dist/` 后
执行对应系统的安装脚本：

UOS / deepin（系统级菜单，需要 sudo）：

```bash
bash right-menu/UOS/1-安装-UOS文件管理器右键菜单.sh    # 安装：写入系统菜单扩展并重启文件管理器
bash right-menu/UOS/2-卸载-UOS文件管理器右键菜单.sh    # 卸载：移除菜单项并重启文件管理器
```

Kylin V10 / MATE（Caja 用户级菜单，不需要 sudo）：

```bash
bash right-menu/Kylin-V10/1-安装-Kylin-V10-Caja右键菜单.sh    # 安装：写入 Caja 脚本菜单
bash right-menu/Kylin-V10/2-卸载-Kylin-V10-Caja右键菜单.sh    # 卸载：删除脚本菜单
```

Kylin V10 SP1（Peony 原生插件，安装时编译，需要开发包与 sudo）：

```bash
bash right-menu/Kylin-V10-SP1/1-安装-Kylin-V10-SP1-Peony右键菜单.sh    # 安装：编译并安装 Peony 插件
bash right-menu/Kylin-V10-SP1/2-卸载-Kylin-V10-SP1-Peony右键菜单.sh    # 卸载：删除 Peony 插件
```

源码目录中脚本正本在 `scripts/right-menu/UOS/`、
`scripts/right-menu/Kylin-V10/` 与 `scripts/right-menu/Kylin-V10-SP1/`，
用法相同（把上面的 `right-menu/` 换成 `scripts/right-menu/` 即可）。

安装脚本会从脚本所在目录逐级向上找 `SVNWorkBench` /
`dist/SVNWorkBench`（脚本放 `dist/right-menu/<系统>/`、工程根目录、
桌面都能用），也支持显式指定：
`bash right-menu/UOS/1-安装-UOS文件管理器右键菜单.sh /path/to/SVNWorkBench`。

**UOS / deepin** 会写入两个菜单项模板（都叫"使用SVN_WB打开"，
按场景各管一段）：

| 文件 | 触发场景 | 传参 |
| --- | --- | --- |
| `SVNWorkBench.desktop` | 右键**文件夹**（`SingleDir`） | `%F` 选中的目录 |
| `SVNWorkBenchEmpty.desktop` | 右键**空白处**（`EmptyArea`） | `%p` 当前所在目录 |

dde-file-manager 6.x 起空白处右键不再展开 `%F`（空白处没有选中项，
`%F` 为空；5.x 时是正常的），所以必须拆成两个文件、空白处改用 `%p`——
两份实测才能两种场景都正常。程序直接取 `argv[0]` 当工作副本目录
（`App.open_wc`），反查地址前会先清空地址框；反查成功后才写配置
（无效路径不会被记住）。

**Kylin V10 / MATE（Caja）** 会写入用户级菜单脚本
`~/.config/caja/scripts/使用SVN_WB打开`，入口是
**右键 -> 脚本 -> 使用SVN_WB打开**：选中目录时打开该目录，选中普通
文件时打开文件所在目录，空白处右键时打开当前目录；不需要 sudo。

**Kylin V10 SP1（Peony）** 与上面的 Kylin V10 / MATE（Caja）是两套
互不相干的方案，**不要混用**。SP1 使用 Peony 原生 C++ 菜单插件，安装
脚本会现场用 qmake/make 编译
`libpeony-svnworkbench-plugin.so` 并安装到
`/usr/lib/<multiarch>/peony-extensions/`，因此**安装时**目标机需要有
Peony 开发包和 Qt5 开发工具：

```bash
sudo apt install g++ make pkg-config qt5-qmake qtbase5-dev libpeony-dev
```

包名以目标机软件源为准，关键是 `pkg-config --modversion peony` 能返回
版本、并且能找到 `menu-plugin-iface.h`。插件元数据版本默认取
`pkg-config --modversion peony`，必须与目标机 Peony 的 `VERSION` 完全
一致（Kylin V10 SP1 当前为 3.2.2），否则 Peony 会静默跳过插件。选中
目录时打开该目录，选中普通文件时打开文件所在目录，空白处右键时打开
当前目录。卸载脚本按 multiarch 目录动态查找并删除插件，不再写死
`aarch64-linux-gnu`，x86_64 机器也能正常卸载。

这些安装脚本都会先检查系统环境（`dde-file-manager` / `caja` /
`peony`），在不适用的系统上直接报错退出，避免把菜单写到错误的位置。

装好后文件管理器里选中目录或右键空白处 ->"使用SVN_WB打开"。

**方式二：用户级注册（免 sudo，任何发行版）**

把下面内容存为 `~/.local/share/applications/SVNWorkBench.desktop`
（`Exec` 换成你实际的程序路径，打包版是 exe，源码版是
`/usr/bin/python3 /path/to/SVNWorkBench.py`）：

```ini
[Desktop Entry]
Type=Application
Name=SVNWorkBench
Comment=用 SVNWorkBench 打开工作副本
Exec=/path/to/SVNWorkBench %F
Icon=kdesvn
Terminal=false
Categories=Development;
MimeType=inode/directory;
```

保存后执行 `update-desktop-database ~/.local/share/applications`（或注销
重登），目录右键的"打开方式"子菜单里就会出现 SVNWorkBench；选中即用该
目录启动程序并自动反查地址。这条路只有"打开方式"入口，空白处右键不会
出现它——**空白处场景请用上面的方式一**（UOS 的双模板、Kylin 的
Caja 脚本与 Kylin V10 SP1 的 Peony 插件都支持空白处右键）。

## 打包交付（双击运行）

`1-构建-打包绿色单文件.sh` 用 PyInstaller 打一个
**绿色单文件**，内置 Python 与 Tkinter 运行时——目标机不用装 python3-tk，
只需系统自带的 svn 命令行：

```bash
./1-构建-打包绿色单文件.sh   # 产物: dist/（主程序 + right-menu/ 各系统脚本）
./2-清理-构建产物与缓存.sh   # 清理: 删 build/ dist/ 与全部 __pycache__
```

- **把 `dist/` 整个目录交给使用者**：双击 `SVNWorkBench` 运行；进入
  `dist/` 后按目标系统执行对应脚本——UOS/deepin 用
  `bash right-menu/UOS/1-安装-UOS文件管理器右键菜单.sh`，
  Kylin V10 用
  `bash right-menu/Kylin-V10/1-安装-Kylin-V10-Caja右键菜单.sh`，
  Kylin V10 SP1 用
  `bash right-menu/Kylin-V10-SP1/1-安装-Kylin-V10-SP1-Peony右键菜单.sh`
  （各自目录里的 `2-卸载…` 卸载）。右键脚本正本在
  `scripts/right-menu/<系统>/` 由开发维护，每次打包自动拷入
  `dist/right-menu/<系统>/`
- Kylin V10 SP1 的右键菜单是安装时现场编译的 Peony 原生插件，执行该
  安装脚本的目标机需要有 `libpeony-dev`、`qt5-qmake`、`qtbase5-dev`、
  `g++`、`make`、`pkg-config`；**只运行主程序不需要这些开发包**。
  编译与插件验证细节见 `scripts/README.md`。
- **PyInstaller 不支持交叉编译**，每个架构在对应架构的机器上构建一次：
  x86 电脑上跑本脚本出 x86 包；把整个项目拷到 ARM 设备上跑**同一份**
  脚本出 ARM 包（脚本与架构无关，按构建机的 Python 版本选 PyInstaller：
  Python 3.8 及以上用 6.x（`pyinstaller<7`），3.7 用 5.x（`<6`），
  3.6 用 4.10，3.5 用 3.6。**实测 Python 3.8 不能用 5.x**，会构建失败；
  构建机上已装的大版本不符时脚本会自动 `pip install --user --upgrade`
  到对应分支，装完仍不符则报错退出）
- 构建机需要 python3、python3-pip、python3-tk——缺 pip 或 tkinter 时
  脚本自动 `sudo apt install` 安装。**python3-tk 必须装在构建机上**
  （tkinter 会打进单文件；构建机缺它时包能打出来，但一运行就报
  `No module named 'tkinter'`），目标机运行时不需要它。缺 pyinstaller
  时脚本自动装，国内网络可设
  `PYPI_MIRROR=https://pypi.tuna.tsinghua.edu.cn/simple`
- 脚本带 `--clean` 强制全新构建（PyInstaller 有增量缓存，不带会空跑
  复用旧产物），并在事后核对 warn 清单确认 tkinter 真的入包
- 拷贝后若双击提示没有执行权限，先 `chmod +x SVNWorkBench`
  （压缩包中转可能丢失可执行位）

## 首次使用

1. 在 **SVN 地址** 行点"仓库浏览"进入仓库，右键"检出到…"勾选目录并指定
   本地目录；或直接在工作副本页选一个已有的工作副本
2. 工作副本是唯一标识：填好（或"浏览"选好）工作副本后，SVN 地址会用
   `svn info` **自动反查回填**（启动时、失焦时、选完目录时、点"刷新"时
   各解析一次）；地址也可手填，手填的不会被覆盖。**反查成功拿到地址后
   会自动刷新改动列表**；路径非法或拿不到地址时什么都不做，也不会把
   无效路径写进配置（启动时发现配置里的路径已失效会一并清掉）
3. 点工作副本行的"刷新"查看本地改动（同一个按钮也会重新反查地址；
   **默认一条都不勾选**，未版本控制与忽略的条目排在列表最后），
   勾选后可添加 / 还原 / 删除 / 提交；
   **双击某一行**弹出对比窗口（键盘 ↑/↓ 移动当前行、空格切换勾选，
   单击/Ctrl/Shift 的选择逻辑同文件管理器，详见下方“改动列表”）；
   需要拉取仓库最新内容时点"更新"

## URL 自动解码

填入的或从工作副本反查到的 SVN 地址若含百分号编码（如
`%E5%9B%BD%E4%BA%A7%E5%8C%96`），保存时自动解码为可读中文
（`国产化`），配置文件与界面中始终显示解码后的地址；svn 命令
会自行处理编码，不影响使用。

## 界面

顶部标题栏：版本号 + "账号管理"按钮（列出 svn 缓存的登录凭据，确认后
删除——删除前逐条展示凭据名称）+ "对比方式"按钮（每次询问 / 总是用
meld / 总是用内置窗口，改动列表右键菜单里也能改）+"主题"按钮（10 套
皮肤单选，默认"晴空"；选中立即生效并记住）。
窗口图标（标题栏 / 任务栏 / Alt+Tab）用内置的 SVN 图标：256x256 PNG
以 base64 内嵌在 `svnwb/appicon.py`，**不需要外部图片文件**（单文件 exe
也能显示），之后打开的仓库浏览器、提交历史、各类弹窗自动继承。
中部是"工作副本"单页（只有一个页面，不再套标签页，省出的高度全给
改动列表）；底部是运行日志与状态栏（就绪 / 运行中 + 取消任务按钮），
运行日志标题行右侧是"清空显示"与"日志文件"（查看、打开历史运行日志）。
进入程序后若工作副本目录存在，会**先反查一次 SVN 地址，成功后再自动
刷新状态**——等窗口首帧渲染完成后再做（不拖慢启动速度），svn 命令都在
后台线程执行。配置里的路径已不存在或不是工作副本时，界面不显示它及
其残留地址，并把这些失效字段从配置里清掉。

### 界面观感（扁平化）

界面用标准库 `tkinter` + `ttk` 做成扁平风格（`svnwb/theme.py`，
**没有引任何第三方皮肤包**），三招：

- **配色**：每套皮肤定义页面底（`APP_BG`）+ 面板（输入框、日志、改动列表、
  树，`SURFACE`）+ 1px 细边框（`BORDER`，替代 Tk 默认的立体凹陷）+ 一个
  强调色（`ACCENT`，用在主操作按钮、选中行、输入焦点框）。默认"晴空"为
  浅灰页面底 + 白色面板；皮肤库 `THEMES` 与派生色计算都在 `core.py`。
- **10 套皮肤即时切换**：顶栏"主题"菜单提供青野 / 晴空 / 深空 / 暖阳 /
  素纸 / 极光 / 原木 / 青竹 / 雾灰 / 暗金，默认**晴空**；选择写入配置，
  下次启动自动恢复。切换只重配颜色，**不重建控件、不动文本内容、选中范围、
  滚动位置、勾选状态与正在运行的任务**。状态色仍保持语义（修改蓝 / 新增绿 /
  删除红 / 冲突橙），深色皮肤下自动提亮到看得清；主色上的文字（按钮/选中
  行）按对比度自动选白色或深色字。
- **扁平化**：ttk 走自带的 `clam` 主题并把 `relief` / `borderwidth`
  归零重配，按钮只剩 1px 细边框（悬停只换底色，没有渐变与凸起）；
  tk 控件的 sunken 立体边换成 `highlightthickness=1`。主操作按钮
  （提交 / 开始下载 / 确定 / 连接 / 信任并重试）用强调色实底，文字按
  对比度自动选白色或深色。
- **内边距**：按钮、表头、树行统一 `padding`，树行高加大到 28px。
- **等高对齐**：按钮与输入框统一 **32px 高**（输入框用 ttk.Entry，
  靠样式 padding 加高——tk.Entry 固定 24px 加不上去），单行的提交说明
  同样凑到 32px；主窗口三行的行标签定宽，几行输入框的左边缘严格对齐
- **按钮定宽对齐**：主界面按钮按排统一宽度（`theme.BTN_W`，≤4 个汉字），
  等距排列，每排最右按钮的右边缘上下对齐成一条竖线；按钮文案也随之
  精简（如"删除"）。各弹窗的同一排按钮也按文案选标准宽或长名宽
  （`BTN_W_LONG`），右缘对齐
- **弹窗宽度统一**：所有模态弹窗（确认 / 对比方式 / 认证 / 证书 / 运行
  日志 / 登录凭据 / 检出勾选）统一为 `theme.DIALOG_W`（640px），非模态
  辅助窗口（仓库浏览 / 提交历史 / 查看内容 / 内置差异）统一为
  `theme.WINDOW_W`（920px），高度仍随内容自适应。确认框不再按“最长
  一行”估算宽度——短路径时窗口只有 200 多像素宽，看起来又窄又高；
  弹窗说明块也按统一宽度自动换行
- **复选框统一**：全程序的复选框都是同一套挑勾字形——`theme.CheckBox`
  （☑ / ☐ 大字号加粗 + 正常文字，覆盖认证"记住密码"、证书"记住此选择"、
  浏览器"信任自签名证书"）；检出 / 更新对话框的勾选栏同样是行内大字形
  ☑/☐（与主界面改动列表同款，见下节）。tk 原生的小方框看不清、
  clam 的 ttk 指示符选中是个"叉"，都不再使用
- **右键菜单同款扁平风格**：仓库浏览器的右键菜单也是面板底色 + 1px 实线
  细边框 + 悬停项强调色实底（不再是系统默认的灰底/立体边菜单）；
  边框不能省——菜单都弹在面板上，无边框会与背景糊成一片、看起来
  像没弹出来
- **弹窗基于父窗口居中**：确认框、凭据/证书弹窗、仓库浏览器、检出/更新
  对话框、提交历史、内置差异窗口等**所有新弹出的窗口都摆到父窗口正中**
  （原先都偏左上角）。部分窗口管理器把窗口坐标当作"含标题栏的框架"
  位置（本机 DDE/KWin 实测客户区还要再偏一个标题栏），程序在首次弹窗
  后**自动标定这个偏移并修正**，之后每个窗口都精确居中
- **子窗口始终压在主窗口之上**：所有子窗口都登记为主窗口的 transient，
  点主窗口、主窗口被置前时也不会把它们盖住（原先会被盖到下面去）
- **模态窗口不会“最小化后卡死主窗口”**：确认框、认证/证书、检出/更新、
  登录凭据、运行日志等模态窗口标记为 dialog，并监听最小化后自动还原。
  模态窗口被最小化时只是看不见，Tk 的 grab 仍然生效，主窗口点哪儿都没
  反应，看起来像程序卡死；现在要么不提供最小化，要么最小化后立刻弹回
- **通知类提示不再弹阻塞式消息框**：任务失败、已有任务在运行、仓库浏览
  或提交历史打开失败等只告诉用户“发生了什么”，改为状态栏右下角常驻
  结果 + 运行日志；运行日志/登录凭据窗口内的“请先选中…”等提示直接写在
  窗口内。只有确认、认证、证书、检出/更新等真正需要用户决策的窗口保留
  模态语义

工作副本页（自上而下：地址行 -> 改动列表 -> 提交）：

- 第一行 **工作副本** 路径 + "浏览" + "刷新"（原"读取地址"已并入
  刷新：先反查 SVN 地址，**成功后**再刷新本地改动列表；路径非法或拿不
  到地址时只提示原因，不刷新、不写配置）；
  第二行 **SVN 地址** + "仓库浏览"（没有工作副本时直接从这里浏览并检出）
  + "显示日志"（打开提交历史窗口）。工作副本是唯一标识，地址由它用
  `svn info` 自动反查回填（启动时、失焦时、选完目录时、点刷新时各解析
  一次），手改过的地址不会被覆盖
- 第三行是勾选与条目操作合并成的**一行**（为了让改动列表更高）：
  左边"全选 / 全不选 / 添加 / 还原 / 删除"，右边是"更新"
  （`svn update` 整个工作副本，完成后自动刷新）；
  勾选计数（已勾选 N / M）在提交行紧挨"提交"按钮。
  改动范围固定为**本地未提交改动**（`svn status --xml --no-ignore`
  ——被 svn 忽略规则命中的文件（如 `.so`）也一样列出，且不带 `-u`、
  不联网）
- **改动列表**：等宽字体（比默认大一号）+ 制表位列（勾选/状态 · 修订 ·
  路径），**默认排序：有改动的排前面（冲突/缺失等异常状态最前），
  未版本控制与忽略的排在最后**；状态用**文字色 + 整行底色**区分
  （修改蓝 / 新增绿 / 删除红 / 冲突·缺失琥珀 / 未版本控制灰），
  状态码为 `?` 未版本控制 / `A` 新增 / `M` 修改 / `D` 删除 /
  `C` 冲突 / `!` 缺失 / `I` 忽略；**选中的行用醒目蓝底高亮**（可多选）；
  **鼠标移入的行会淡色高亮**（光标保持系统样式，不换成手型），移出即
  消失。勾选框用**挑勾字形 ☑（已勾选）/ ☐（未勾选）+ 独立的大字号
  加粗**，在默认等宽字体下也只有 8px 宽、几乎看不清，所以单独放大；
  正文与勾选框**垂直居中对齐**（勾选框字形大、两者共用基线时正文会
  偏低，已做像素级微调）。
  **行选择与勾选是两套独立状态**：☑/☐ 决定提交、还原、添加、删除；
  行高亮只表示"当前选中的行"，不改变任何勾选。
  **默认一条都不勾选**——提交、还原、添加、删除都必须先手动勾选；
  **选择逻辑同文件管理器**：普通单击正文只高亮当前行、勾选不变；
  **只有点中 ☑/☐ 字形本身才切换勾选**（点状态文字/正文不算，字形左右
  留几像素方便点中）；被点行在多行高亮选区内时，**整个选区跟着同步成
  同一状态**，未高亮的行只切换它自己；**Ctrl+左键**增/减单行高亮；
  **Shift+左键**高亮锚点到该行的整段并清空段外；
  **Ctrl+Shift+左键**把整段追加到高亮选区；点空白处清空高亮；
  **Ctrl+A** 全选高亮行（不勾选任何条目）。锚点是上次普通/Ctrl 单击或
  键盘移动的行，连续 Shift 点击不漂移；**支持键盘操作**：
  ↑/↓（PgUp/PgDn/Home/End）移动当前行，**Shift+方向键（含
  PgUp/PgDn/Home/End）**从锚点扩展/收缩高亮选区（锚点不动、勾选不变）；
  **空格批量切换高亮选区的勾选**
  （全部已勾选 -> 全部取消，否则全部勾选；没有选区时切换当前行）。
  右键菜单里另有"勾选所选条目 / 取消勾选所选条目"，右键点在高亮选区内
  会保留多选，批量项作用于整个选区
- "删除"执行 `svn delete --force`：版本控制的条目被标记删除
  （本地文件立即移除，提交后从仓库移除），未版本控制/忽略的条目直接从
  磁盘删除；删除前弹确认框逐条列出所选条目
- "还原"执行 `svn revert`：普通修改只恢复勾选的条目（不碰同目录下
  没勾选的文件）；**新增 / 删除 / 缺失的目录会连同其下所有条目一起
  恢复**（svn 不允许只恢复父目录而不恢复孩子）——"添加"后想取消添加，
  勾选该目录点"还原"即可，本地文件保留、重新变成未版本控制；
  删除的目录连同子目录/文件一起回到工作副本；恢复前弹确认框列出所选条目
- **单击**高亮选中该行（不改变勾选，Ctrl/Shift 可多选）；
  **双击某一行弹出对比窗口**，对比方式由用户选择：
  - 装了 meld 时弹"选择对比方式"小窗：**meld 对比**（导出该文件的
    BASE 基线到临时文件，交给 meld 左右对比；新增 / 未版本控制等没有
    基线的条目用空文件占位，本地已删除的条目用空文件当右侧内容）或
    **内置窗口**（跑 `svn diff`，在程序内显示彩色差异）。勾选"记住我的
    选择"后不再询问，之后可随时从顶栏"对比方式"或改动列表右键菜单改回
    "每次询问" / "总是用 meld" / "总是用内置窗口"
  - 没装 meld，或该条目是目录：不询问，直接用内置差异窗口
    （新增绿 / 删除红 / 标题灰 / 变更块蓝，顶部统计行数与变更块数）
  - 未版本控制 / 忽略的条目没有 BASE 基线（`svn diff` 会报 E155010），
    选内置窗口时直接读取本地文件、按"全新增"渲染（二进制文件给提示，
    超大文件截断）
  - 改动列表右键菜单与仓库浏览器同款：**用 meld 对比** / **用内置窗口
    对比**（本次有效，不改全局设置）/ **查看提交历史**（版本控制条目按
    该条目的仓库地址打开，未版本控制/忽略/新增退回整个工作副本）/
    分隔线 / **对比方式**子菜单（每次询问 / 总是用 meld / 总是用内置窗口）；
    同一个内置窗口重复使用（双击另一行直接换内容），Esc 关闭；对比用的
    临时文件在退出程序时清理
- **提交说明**（单行高，可粘贴多行）+ "提交"：**只提交勾选的条目**，
  一条都没勾选时会提示先勾选（不再默认提交整个工作副本）；提交前确认
  （清单或说明过长时内容区自动限高并滚动，底部确认按钮始终可见），
  成功后显示新版本号、自动刷新，并**清空提交说明框**（避免旧说明被原样
  带进下一次提交）；svn 提示"没有需要提交的改动"时保留已写的内容
  （中英文语言环境的 svn 输出均可识别版本号）

运行日志默认折叠，只留一行标题，**任务启动时也不会自动展开**——
只有点标题（`▸ / ▾ 运行日志`）才展开/收起，状态保持到下次点击。
标题行右侧是"清空显示"与"日志文件"（查看、打开历史运行日志），
其中"日志文件"在"清空显示"后面。
任务运行结果显示在状态栏右下角（成功绿 / 警告橙 / 失败红），
**不会自动消失**，直到下一条结果把它覆盖；提交、删除等操作完成后的
"提交成功 / 已删除所选条目"不会被随后的自动状态刷新盖掉。

其他：

- 输入框快捷键：Ctrl+A 全选，Ctrl+C/X/V 复制/剪切/粘贴
  （只读的日志区同样可全选复制；**查看内容**与**内置差异**窗口还支持
  点击正文后 Ctrl+A/Ctrl+C，以及右键 **复制 / 复制全部内容 / 全选**）
- 任务运行中按钮自动禁用，同一时刻只允许一个任务
- 关闭窗口时若有任务在运行，会询问是否退出并取消任务
- 工作副本与 SVN 地址**只有反查成功（确认是有效工作副本）后才写入
  配置**；路径非法/不是工作副本时绝不落盘，重启也不会显示无效路径和
  残留地址（配置里已有的失效字段会在启动时清掉）。
  从仓库浏览器检出或更新成功后也会**自动写回配置**，下次打开浏览器
  直接带出

### 下载与更新

下载只有一个入口：**仓库浏览器**（见下节）。SVN 地址行的"仓库浏览" ->
选中目录 -> 右键"检出到…"（或工具栏"检出…"）-> 勾选要下载的目录与文件
-> 确认。对话框（"检出 / 更新"窗口）：

- **目录层级一目了然**：行首是折叠箭头（`▾` 已展开 / `▸` 可展开）
  与 ☑/☐ 勾选框，缩进表示层级，目录名用强调色并以 `/` 结尾；
  未展开的目录显示"（加载中…）"占位，读空的显示"（空目录）"
- **目录与文件都能勾选**（☑ 下载 / ☐ 排除）：`--set-depth=exclude`
  对文件同样有效。勾选会向上补齐祖先、向下传播到已加载的子孙；
  支持全选 / 全不选 / 反选
- **单击只选中行（高亮），不改变勾选状态**；点 ☑/☐ 或按空格才翻转
  勾选；双击目录行展开 / 收起
- **翻转勾选时列表不进不退**：点 ☑/☐ 或按空格只重画受影响的行，列表
  既不跳回顶部、也不把选中项滚到眼前
- **键盘操作**：↑/↓（PgUp/PgDn/Home/End）移动当前行，空格勾选 /
  取消勾选，← 收起或跳到父目录，→ 展开或跳到第一个子目录
- **本地目录实时校验**：输入框内容变化 400ms 后立即校验（失焦立即），
  路径被文件占用或不是目录时给出错误提示并**禁用确认按钮**；
  留空时提示"请填写本地目录"
- 对话框底部按钮按本地状态自动切换：
  - 本地目录不存在或是空目录 -> **开始下载**（首次检出）
  - 本地目录已是**同一地址**的工作副本 -> **更新到所选**：
    重新勾选的目录/文件会被拉回，取消勾选的会被排除，其余内容增量更新
  - 本地目录是**其他来源**的工作副本 -> 按钮禁用并给出提示，避免误覆盖
  - **窗口立即弹出**：打开时只同步跑毫秒级的 `svn info`；本地实际排除
    状态（`svn status -v --xml`，被 `--set-depth=exclude` 排除的条目不在
    输出里）由后台线程接着读，读完前按钮暂显示"正在读取本地排除状态…"并
    禁用——大工作副本上读得慢也不再卡住弹窗，**已排除的条目显示为 ☐**，
    随时可以重新勾选；本地尚无工作副本时，初始勾选取自配置里的排除清单
  - **点"开始下载"后只剩主窗口**（用户要求）：仓库浏览器、提交历史、
    内置差异等辅助窗口自动关闭，主窗口回到前台，状态栏提示"正在下载到
    <本地目录>，请稍候…"，右下角蓝字提示"下载已开始，可随时点
    「取消任务」中断"（完成后自动换成结果提示）；"更新到所选"不关窗

下载逻辑：
- 目标目录不存在：先 `checkout --depth=immediates` 检出根目录，再逐层
  递归——命中排除项 `set-depth=exclude`；路径下方还有排除项
  `set-depth=immediates` 继续向下；其余 `set-depth=infinity`；
  中途取消后重试会自动续齐（已下载部分不重复获取）
- 目标已是**同一来源**的工作副本（`svn info` 校验 URL）：自动改为
  `svn update` 整树增量更新，仅同步有变化的内容；随后按本次勾选对齐——
  先对"重新勾选的条目"执行 `--set-depth=infinity` 拉回，
  再对"取消勾选的条目"执行 `--set-depth=exclude` 排除
- 目标已是**其他来源**的工作副本：拒绝执行并提示两个来源地址，避免误操作

### 仓库浏览
- SVN 地址行的"仓库浏览"按钮打开独立窗口：地址栏（回车或"转到"）+
  左侧目录树 + 右侧条目列表（名称 / 后缀 / 版本 / 作者 / 大小 / 日期；
  名称列带文件夹/文件图标并向内留出缩进，后缀与大小对目录留空；
  **所有列（含表头）一律左对齐**，左侧目录树也带文件夹图标，
  图标与文本之间留 5px 透明间隙）
- **地址栏是带历史记忆的可编辑下拉框**：手输地址后回车或点"转到"；
  也可以展开下拉列表，从**最近浏览**过的地址里选（选中即跳转）。
  只有点"转到"（含回车、从下拉选历史）且读取成功才记入历史；在树中
  展开、双击目录或点"刷新"等普通浏览**不会**改写历史（最新在前、按地址
  去重、最多 10 条，显示解码后的可读地址），写入配置 `recent_repo_urls`；
  地址栏右键"清除最近记录"可一键清空，没有历史时该项置灰
- 目录树**按需懒加载**：展开某个目录时才读取其子目录，
  树中只放目录，文件见右侧列表；右侧双击目录可跳转到对应树节点
- **仓库集合根**（如服务器根下的 `/svn` 多仓库入口）：
  普通 `svn list` 会报"URI 不含仓库名"，工具自动改用同一地址的
  mod_dav_svn 网页索引读取仓库清单；左侧树根显示为**仓库列表**，
  右侧列出服务器索引里的仓库，双击仓库进入后按普通目录继续懒加载。
  只展示索引实际列出的仓库，不硬编码服务器地址或仓库名，也不自动
  补充索引里没有的独立仓库；集合根本身不是具体仓库，检出 / 导出 /
  查看提交记录菜单置灰，选中其中的仓库后才可用。集合根读取依赖
  服务器的 HTTP(S) 网页索引；`svn://` 等协议请直接填写具体仓库地址
- 读取集合根索引时优先复用 svn 已缓存的登录凭据（`svn.simple`，
  按 scheme/host/port 同源匹配），没有可用凭据或验证失败再弹登录框；
  证书错误复用"信任自签名证书"开关与证书确认弹窗
- 右键菜单：目录（左树节点 / 右侧行 / **右侧空白处**）为
  **检出到… / 导出到… / 刷新此节点 / 查看提交记录 / 复制地址**，
  文件行是**查看内容 / 查看提交记录 / 导出到… / 复制地址**。
  "复制地址"复制的是**解码后的可读地址**（中文、空格等不再带
  `%E4%B8%AD` 这类百分号编码）。
  右侧列表**空白处**右键作用于当前目录（空白处也能"查看提交记录"）；
  "查看提交记录"把提交历史窗口切到**选中路径的地址目标**，
  不依赖主界面的工作副本
- **检出到…**：勾选要下载的目录与文件（☑ 下载 / ☐ 排除）；目录层级
  清晰（箭头 + 缩进 + 强调色目录名），单击只选中、点 ☑/☐ 或按空格才
  翻转勾选，支持键盘操作与本地目录实时校验（详见上节"下载与更新"）；
  勾选会自动向下传播到已加载的子目录、向上补齐祖先；填写本地目录后
  确认，完全复用下载任务链路（同样的确认弹窗、同样的逐层 set-depth
  算法）。本地已是同源工作副本时即为**更新**，按钮与确认文案随之切换
- **导出到…**（不是检出）：选一个本地文件夹，`svn export` 一份
  **不含 .svn** 的干净副本到"文件夹/节点名"，单个文件也能导出；
  目标已存在时先确认、确认后带 `--force` **覆盖同名文件**
  （目标里的其他文件不动）。导出走主界面任务链路（可取消、有运行
  日志），**不建工作副本、不写配置**，浏览器保持打开可接着导出
- **查看内容**：文件行右键"查看内容"或**双击文件**打开只读内容窗口
  （`svn cat` 读 HEAD 版本，等宽字体、可横滚、可选中复制、Esc 关闭）；
  点击正文即可获得焦点，支持 Ctrl+A 全选 / Ctrl+C 复制；右键菜单提供
  **复制 / 复制全部内容 / 全选**；
  文本编码**自动适配**（UTF-8 / GB18030 / Big5 / Shift-JIS / EUC-KR /
  Latin-1，UTF-16 按 BOM 或字节分布识别），状态栏显示识别出的编码，
  底部"编码"按钮可手动切换；二进制文件只提示不渲染乱码、超大文件截断显示
- 窗口右下角"信任自签名证书"（☐ / ☑ 大字形复选框）：勾选后写入配置，
  浏览与检出共用
- 浏览窗口只看 HEAD 版本；要看**历史提交**用右键"查看提交记录"
  （直接以选中路径为目标）或 SVN 地址行的"显示日志"
- 读取目录走独立后台线程，与主界面任务互不干扰：
  浏览时不会触发"已有任务在运行"，任务运行中也能照常查看仓库
- 认证 / 证书弹窗与主界面是同一套；浏览过程不写运行日志

### 提交历史

SVN 地址行的"显示日志"按钮打开独立窗口（`svn log`，走主界面的单任务链路，
所以凭据弹窗、运行日志、取消按钮与其它任务一致）：

- 上半部是提交列表：**修订 / 作者 / 时间 / 说明首行**（多行说明以 `…`
  结尾），默认读最近 50 条，"条数"可改；点"刷新"重新读取
- 中部是**选中版本的完整提交说明**（只读、按词换行，只占 3 行、超长
  可滚动查看、可选中复制）：列表"说明"列只放得下首行，多行长描述在这里
  看全；3 行是刻意的——再高会把下面的改动列表挤出可视区（用户反馈）
- 下半部是**选中版本改动的文件列表**（改动类型 A 添加 / M 修改 /
  D 删除 + 仓库路径），来自同一次 `svn log -v` 输出，选中即显示，不用再查
- **双击某个版本**（或选中后点"对比改动"）：跑 `svn diff -c 该版本`，
  对比的正是**本次提交与上一个版本之间**的差异（`-c N` = rN-1 → rN，
  不含本地未提交改动），窗口标题与状态栏都会写明"rN 相比上一版本 rN-1"。
  统一差异弹主界面的**内置彩色差异窗口**（差异超过两万行自动截断，
  防止超大版本把界面卡死）；**不会把 .diff 丢给 meld**——meld 3.20 的
  命令行打开不了补丁视图，只会拿 diff 文件和它自己对比
- **双击某个文件行**：只对比该文件在该版本的改动，**一律按仓库地址
  对比**（本版本新增/删除、或本地被排除的文件同样成立，不会报
  "找不到节点"）：对比方式与主界面共用（每次询问 / 总是 meld / 总是
  内置，也可在弹窗里记住）——选 meld 时分别导出 rN-1 与 rN 两版原始
  内容，meld **左右两版**对比（左上一版本、右本次提交）；选内置走统一
  差异进内置窗口。没装 meld 时不询问、直接内置；拿不到仓库根地址时
  降级为整版本对比（整版本始终用内置，不询问）。
- **两种目标**："显示日志"按钮读当前工作副本；仓库浏览器右键
  "查看提交记录"读选中路径的地址（窗口标题显示目标），
  之后点主界面的"显示日志"可随时切回工作副本目标
- 与改动列表的双击对比一样，临时文件在退出程序时清理

### 凭据与证书
- 遇到认证错误（E170001/E215004 等）自动弹出"需要 SVN 身份验证"窗口，
  输入用户名/密码后自动重试当前命令并对本次任务后续命令生效
- 可勾选"让 svn 记住密码"（由 svn 缓存，明文存于 ~/.subversion，默认不勾选，
  未勾选时附加 `--no-auth-cache` 仅本次会话有效）
- 遇到证书错误（E230001）弹窗询问是否信任并重试；勾选"记住此选择"
  会写入配置，之后自动信任
- 顶栏"账号管理"窗口列出 svn 缓存的登录凭据（`~/.subversion/auth/
  svn.simple` 下每文件一条；显示凭据名称——svn 的认证域 realm——与
  用户名、缓存文件）。选中一条或多条后点"删除所选…"，**确认框逐条展示
  凭据名称**，确认才删除对应文件并**立即刷新列表**，svn 下次连接会重新
  询问用户名/密码
- **密码在界面日志与日志文件中均以 `******` 打码**

## 常见问题

- **错误: 未找到 tkinter 图形库**：`sudo apt install python3-tk`
- **错误: 无法连接图形界面**：在无图形界面的服务器上无法运行，
  请到有桌面的机器上执行
- **svn: command not found / 未检测到 svn**：`sudo apt install subversion`
- **"刷新"提示不是工作副本**：该目录没有 `.svn`，请换个目录或先检出
- **认证弹窗反复出现**：用户名或密码不正确，或账号无该路径权限
- **运行日志在哪**：`/tmp/SVNWorkBench-<用户名>/logs/` 文件夹，
  或点运行日志标题行右侧的"日志文件"
- **换了版本配置丢了**：v5 的配置在 `~/.config/SVNWorkBench/`；
  首次启动会自动从旧版程序目录的 `configs/_settings.json` 迁移
